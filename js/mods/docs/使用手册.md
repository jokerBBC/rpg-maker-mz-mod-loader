## 一、游戏制作者

### 1.1 将 ModLoader 接入自己的游戏

ModLoader 以 `js/mods/ModLoader.js` 形式分发，推荐 **注入模式**（插件模式亦可，但需注意加载时序）。

**注入模式（推荐）**：修改游戏根目录 `index.html`，在 `main.js` **之前**插入：

```html
<script type="text/javascript" src="js/mods/ModLoader.js"></script>
```

**插件模式**：在 RMMZ 插件管理器中添加 `ModLoader.js`。

随游戏更新时，一并推送 `js/mods/` 目录（含 `ModLoader.js`、`config/`、`docs/` 等）。玩家 Mod 配置保存在 `mod_config.json`，**不写入** `plugins.js`，官方插件更新后 Mod 开关不会丢失。

### 1.2 开启 Steam 创意工坊

编辑 `js/mods/config/modloader_config.json` 的 `workshop` 段：

```json
{
  "ml_theme": "dark",
  "ml_language": "zh_CN",
  "workshop": {
    "enabled": true,
    "steamAppId": "你的游戏AppID",
    "steamLibraryPath": ""
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `workshop.enabled` | `true`：扫描并加载工坊 Mod；`false`：保留「创意工坊」筛选入口，列表提示「游戏未开启创意工坊功能」，不扫描 |
| `workshop.steamAppId` | **必改**为你的 Steam AppID（与 `steam_appid.txt`、Steamworks 工坊后台一致）。仓库示例 `4379740` 仅用于本仓库联调 |
| `workshop.steamLibraryPath` | 一般留空；Steam 装在非默认库盘或多库时填**库根**，如 `D:/SteamLibrary` |

#### 盗版环境检测（可选 · libs 扩展）

将 `js/mods/libs/piracyGate.js` 随发行包推送即开启；**删除该文件即关闭**。检测逻辑与文案在扩展内，通过 `registerManagerGate` 挂载，无需改 `ModLoader.js`。

> **说明**：V3.16.1 曾内置固定检测；V4.1.1～V4.1.5 用 `piracyDetection.enabled` 配置开关；**V4.1.6 起改为 libs 文件有无控制**。旧配置里的 `piracyDetection` 段可删除，管理器不再读取。

> **工坊与路径**：创意工坊功能依赖 Steam 正版安装路径解析 `steamapps/workshop/content/`。非正版环境无法使用工坊；未放置 `piracyGate.js` 时本地 Mod 管理不受路径限制。

开通工坊后，将 `workshop.enabled` 设为 `true` 并填入正确 AppID，**随游戏更新推送给玩家**即可。

### 1.3 开启创意工坊后如何自测

1. 确认 `workshop.enabled: true`，AppID 正确，游戏为 Steam 正版启动  
2. F5 进游戏 → 打开 Mod 管理器 → 左下角版本应为 **V4.2.0**（或当前发布版）  
3. 筛选 **创意工坊**，应能看到已订阅的测试包  
4. 点击 **刷新列表**，列表应更新；工坊场景下 `_workshop/<fileId>/` junction 应重建  
5. 开启测试 Mod → **保存** → F5，确认游戏正常启动且 Mod 生效  

**本仓库联调自测包**（AppID `4379740`）：

```
<Steam库>/steamapps/workshop/content/4379740/
  3000000001/   # 单脚本 + manifest + preview
  3000000002/   # 依赖 3000000001（@base）
  3000000003/   # 无 modloader.json，单脚本
  3000000004/   # 多脚本包（3 行列表）
```

各包脚本、`preview.png`、`modloader.json` 均在 **包根目录**（V4.1 扁平布局，无 `js/mods/` 子目录）。详细测试项见 [`ModLoader_测试文档.md`](ModLoader_测试文档.md)。

**发布前检查**：

- 工坊包结构与本地 `_localmods` 包结构一致（见 [3.2 包结构规范](#32-包结构规范)）  
- `modloader.json` 的 `entries` 仅写文件名，禁止路径  
- 详情区 preview 可显示；缺失时显示「无预览图」  

### 1.4 管理器语言包如何拓展

管理器 UI 文案位于 `js/mods/config/language/`：

```
config/language/
├── zh_CN.json
├── zh_TW.json
└── en.json
```

**添加新语言**：

1. 复制 `zh_CN.json` 为 `ja.json`（示例）  
2. 修改文件头元数据：
   ```json
   {
     "_langCode": "ja",
     "_langName": "日本語",
     ...
   }
   ```
3. 翻译其余键值（键名不可改，仅改值）  
4. F5 重开管理器 → ⚙ 系统设置 → 语言下拉应出现新项  

**翻译查找链**：当前语言 → `zh_CN` → 键名原文（不崩溃）。

Mod 插件内的 `@text` 参数别名由 Mod 作者自行定义，与管理器语言包无关。

**Mod 商店拓展**（有 `libs/modStore.js` 时）：面板文案内嵌于 `modStore.js` 顶部的 `STORE_I18N_PACKS`（zh_CN / zh_TW / en），同样读取 `modloader_config.json` → `ml_language`；**不**写入 `config/language/`。切换语言后须**重新打开** Mod 商店面板（或重开管理器）才刷新商店文案。贡献新语言时须同步维护 `STORE_I18N_PACKS` 与管理器语言包，详见 [`mod商店拓展plan.md`](mod商店拓展plan.md) §14。

### 1.5 开启 Mod 商店拓展（可选 · libs 扩展）

未开通 Steam 创意工坊时，可用 **Mod 商店** 让玩家从 HTTPS catalog 订阅、下载、更新 `_localmods` 整包。创意工坊 Mod 仍由 Steam 更新，商店不介入工坊。

将 `js/mods/libs/modStore.js` 随发行包推送即开启；**删除该文件即关闭**（与 `piracyGate.js` 同模式）。通过 `registerLogEntry` 挂载 **设置 → Mod 商店** 入口，无需改 `ModLoader.js`。

**可选预填订阅源**：编辑 `js/mods/config/mod_store.json`（首次运行也会自动生成）。整合包可预置 `sources`，玩家打开游戏即可在商店看到 Mod：

```json
{
  "maxDownloadBytes": 104857600,
  "sources": [
    {
      "id": "my-source",
      "name": "我的 Mod 源",
      "catalogUrl": "https://gitee.com/用户名/仓库名/raw/master/catalog.json",
      "enabled": true
    }
  ],
  "suppressInstallHint": false,
  "seenMods": {}
}
```

| 字段 | 说明 |
| --- | --- |
| `sources[].catalogUrl` | 须为 `https`；推送成功后作者打包工具日志中的 Catalog URL |
| `maxDownloadBytes` | 单包下载体积上限，默认 100MB；玩家可在商店「订阅管理」调整 |
| `seenMods` | 运行时写入，记录玩家已查看的包名（「新增」提醒） |
| `suppressInstallHint` | 玩家勾选「不再提示」后由运行时写入 |

玩家用法见 [2.6 Mod 商店](#26-mod-商店)；作者打包见 [3.5 通过 Mod 商店发布](#35-通过-mod-商店发布) 与 [`tools/modstore/gui/README.md`](../tools/modstore/gui/README.md)。设计细节见 [`mod商店拓展plan.md`](mod商店拓展plan.md)（含 §14 商店多语言扩展说明）。

### 1.6 开启管理器在线更新（可选 · libs 扩展）

发行包内含 `libs/modLoaderUpdater.js` 时，玩家可在 **设置 → 管理器更新** 中手动检查并更新 ModLoader 本体（`ModLoader.js`、`libs/`、`docs/`、语言包、`tools/` 等白名单文件）。**与 Mod 商店完全分离**，不碰玩家 `_localmods`。

将 `js/mods/libs/modLoaderUpdater.js` 随发行包推送即开启；**删除该文件即关闭**。无需改 `ModLoader.js`。

| 项 | 说明 |
| --- | --- |
| 远程源 | 写死 [GitHub](https://github.com/jokerBBC/rpg-maker-mz-mod-loader) / [Gitee](https://gitee.com/Jokerbbc/rpg-maker-mz-mod-loader)；简中 / 繁中默认 Gitee |
| 玩家偏好 | `js/mods/config/modloader_updater.json`（运行时自动生成；**永不被在线更新覆盖**） |
| 禁用更新 | 面板勾选「禁用管理器更新」→ 不拉 channel、无绿色角标、隐藏检查/更新按钮 |
| 剔除 Mod 商店作者工具 | 默认勾选；在线更新跳过 `tools/modstore/`；不删除本地 tools 目录 |
| 作者发版 | `node tools/manager-release/sync.js` → 同步到 `D:\dev\rpg-maker-mz-mod-loader` 并生成 `manager/channel.json` + `manager/catalog.json`；作者自行 push 并打与 `VERSION` 同名 tag |

玩家用法见 [2.8 管理器更新](#28-管理器更新)；设计细节见 [`管理器在线更新plan.md`](管理器在线更新plan.md)。

## 二、玩家

### 2.1 基本使用

1. 进入游戏，点击左上角 **模组管理器**  
2. 用 **全部 / 本地 / 创意工坊** 筛选列表；可点 **刷新列表** 重扫本地与工坊  
3. 选中 Mod，右侧查看详情（来源、依赖、参数等）；若 Mod 包写了版本且根目录有 `CHANGELOG.md`，版本旁会出现 **更新日志** 链接  
4. 开关 Mod；有 ⚙ 的可改参数；改完点 **保存**  
5. **F5 刷新游戏**，开关与参数才会生效  

> 修改 Mod 开关、参数或排序后必须 F5。工坊 Mod 请在 **Steam 客户端** 订阅/取消订阅；游戏内仅开关、排序与改参。从 Mod 商店下载/更新后，点 **刷新列表** 即可在主列表看到新包（不必 F5）。

### 2.2 本地 Mod 与创意工坊 Mod

| 类型 | 来源 | 能否删除 | 能否拖放安装覆盖 |
| --- | --- | --- | --- |
| **本地** | `js/mods/_localmods/<包名>/` | 可以（整包删除） | 可以 |
| **创意工坊** | Steam 订阅，经 `_workshop/` 桥接加载 | 不可以 | 不可以 |

工坊 Mod 在列表中带 **工坊** 角标；删除模式下工坊行 **不显示** 垃圾箱。工坊 Mod **可排序**（需在「全部」筛选下）。

### 2.3 安装本地 Mod

打开管理器 → **安装 Mod** 入口：

| 方式 | 说明 |
| --- | --- |
| 拖放 `.js` | 自动安装到 `_localmods/<基名>/<基名>.js` |
| 浏览选 `.js` | 同上，可多选 |
| 拖放整个 `mods` 文件夹 | 合并复制到 `js/mods/` 根（含 `_localmods`、config 等） |

无效拖放（非 `.js` 且非 mods 文件夹）会提示：**拖放安装仅支持：.js 文件或 mods 文件夹！**

### 2.4 配置保存在哪

| 文件 | 内容 |
| --- | --- |
| `js/mods/mod_config.json` | 各 Mod 开关、参数、排序（唯一配置源） |
| `js/mods/config/modloader_config.json` | 管理器主题、语言、工坊开关 |
| `js/mods/config/mod_store.json` | Mod 商店订阅源、`maxDownloadBytes`、`seenMods` 等（有 `modStore.js` 时） |
| `js/mods/config/modloader_updater.json` | 管理器更新偏好（`updatesDisabled` 等；有 `modLoaderUpdater.js` 时） |
| `js/mods/libs/` | 依赖库（如 `marked.min.js`）与可选扩展（如 `piracyGate.js`、`modStore.js`、`modLoaderUpdater.js`） |

**V4.1.1 起**：若你从旧版升级，`mod_config.json` 里可能仍是 `../mods/<名>` 旧键。打开管理器后 **保存一次**，会自动改写为 `local:<包名>:<脚本基名>` 新键，无需手动改 JSON。

### 2.5 从旧版整合包升级（V4.1）

1. 备份 `js/mods/config/` 与 `js/mods/mod_config.json`  
2. 删除 `js/mods/` 下除 `config/` 和 `mod_config.json` 外的内容  
3. 覆盖作者提供的新版 `mods` 文件夹（已含 `_localmods/` 及修复后的资源路径）  
4. F5 进游戏 → 打开管理器确认开关/参数 → **保存** → 再 F5  

Mod 脚本与资源路径需使用新版包结构；仅保留旧 `mod_config.json` 不够，必须搭配新版 Mod 文件。

### 2.6 Mod 商店

需发行包内含 `libs/modStore.js`。入口：**模组管理器 → ⚙ 设置 → Mod 商店**。

**界面语言**：与主管理器一致。在 ⚙ **系统设置 → 语言** 选择简体中文 / 繁體中文 / English 后，重新进入 Mod 商店即可看到对应文案（设置菜单中的「Mod 商店」入口标签亦会同步）。

**订阅**：在商店内打开 **订阅管理**，添加 Catalog URL（须 `https`）。整合包若已预填 `mod_store.json` 的 `sources`，可跳过手动添加。

**浏览**：

| Tab | 说明 |
| --- | --- |
| 来源 | `全部` + 各已订阅来源 |
| 状态 | `全部` \| `可更新` \| `新增` \| `未下载` |

进入商店时状态 Tab 会智能默认（有可更新 → 可更新；否则有未下载 → 未下载；否则全部）。列表显示本地/商店版本、包大小、来源；多源同名包带「多源」标记。

**操作**：

| 按钮 | 说明 |
| --- | --- |
| 下载 / 更新 | 未安装或商店版本更高时可用；显示进度、速度、ETA |
| 更新已安装 | 批量更新；**跳过多源** Mod（须逐条选手动更新） |
| 刷新 | 重新拉取各源 catalog |
| 订阅管理 | 增删源、启用/禁用、调整单包体积上限（MB） |

**角标**：设置齿轮左侧绿色数字 = 可更新 + 未读「新增」Mod（按包名去重）；点击列表条目后标记已读。右侧红色 `!` 仍为冲突日志（与商店无关）。

**装完后**：回到主界面点 **刷新列表**，新包出现在本地 Mod 列表；再按需开关 Mod 并 **保存**，**F5** 生效。

**大包**：catalog 中 `size` 准确且 **>50MB** 时支持断点续传（服务器须支持 HTTP Range）。Gitee 仓库 raw 单文件约 50MB 上限，大包请用 Release / CDN，catalog 只改 `downloadUrl`。

### 2.8 管理器更新

需发行包内含 `libs/modLoaderUpdater.js`。入口：**模组管理器 → ⚙ 设置 → 管理器更新**（与 Mod 商店为两个独立卡片）。

**界面语言**：内嵌于 `modLoaderUpdater.js` 的 `I18N_PACKS`（简中 / 繁中 / English），跟随 `modloader_config.json` → `ml_language`；重新打开面板后刷新文案。

**操作**：

| 按钮 / 选项 | 说明 |
| --- | --- |
| 检查更新 | 拉取 `main/manager/channel.json` 得 tag，再拉同 tag 的 catalog，比对本地 / 远端版本 |
| 更新 | 仅在有新版本且未禁用时可用；主区域显示升级过程日志（跳过、下载、备份、替换、清理） |
| 复制日志 | 复制纯文本日志，便于贴给作者排查 |
| 禁用管理器更新 | 勾选后不拉 channel、齿轮绿色角标不计入、隐藏检查/更新按钮 |
| 不下载 Mod 商店作者工具 | 默认勾选；在线更新跳过 `tools/modstore/`（打包 GUI 等）；**不删除**本地 `tools/` 下文件 |

**角标**：设置齿轮左侧绿色数字 = 各 `registerLogEntry` 的 `getUpdateCount` **之和**（Mod 商店可更新数 + 管理器 `0|1`）；为 0 时不显示。

**完成后**：日志提示 **请按 F5 刷新游戏**；管理器脚本与 libs 变更须 F5 后生效（含更新器自身）。

**说明**：本通道只更新管理器白名单文件，**不**更新玩家 `_localmods`；Mod 仍走 [2.6 Mod 商店](#26-mod-商店) 或整合包 / 手动覆盖。

### 2.7 查看更新日志

| 入口 | 内容 |
| --- | --- |
| 管理器左下角 **(日志)** | ModLoader 自身更新说明（`docs/modloader_CHANGELOG.md`） |
| 详情面板版本旁 **更新日志** | 当前 Mod **包** 的 `CHANGELOG.md`（须同时有版本号；多脚本包共用包根一份） |
| Mod 商店列表 **更新日志** | 按 catalog `changelogUrl` 拉取；已最新时优先读本地包根文件 |

三处均使用同一 Markdown 弹窗样式；ESC / 遮罩 / 关闭按钮可退出。

## 三、Mod 作者

### 3.1 元数据规范

Mod 为 RMMZ 插件格式，文件头注释需包含：

```javascript
/*:
 * @target MZ
 * @plugindesc 我的 Mod 简介
 * @author 作者名
 * @version V1.0.0
 *
 * @param myOption
 * @text 选项显示名
 * @type number
 * @default 1
 * @min 0
 * @max 10
 *
 * @help
 * 帮助文本（支持 Markdown 风格换行）
 */
```

**常用标签**：

| 标签 | 说明 |
| --- | --- |
| `@text` | 参数在管理器中的中文显示名 |
| `@base` | 前置依赖（空格分隔多个插件名，可带或不带 `.js`） |
| `@orderAfter` | 应排在某插件之后 |
| `@orderBefore` | 应排在某插件之前 |
| `@define-schema` / `@schema` | struct / table 模板定义 |

**依赖检测**：管理器先查游戏原生插件，再查列表内全部 Mod（含工坊）。游戏原生插件已开启则顺序天然满足。

**参数类型**（所有 `@param` 必须提供 `@default`，否则参数编辑会被锁定）：

| `@type` | 说明 | 常用标签 |
| --- | --- | --- |
| `number` | 数值（双侧 `min`/`max` 时显示滑动条） | `@min` `@max` `@step` |
| `boolean` | 开关 | — |
| `string` | 单行文本 | — |
| `select` | 单选下拉 | `@option` |
| `color` | 颜色 | — |
| `note` / `multiline_string` | 长文本（多行） | — |
| `struct` | 结构体 | `@schema` |
| `table` | 表格列表 | `@schema` |
| 数据库引用 | 见下表 | — |

**数据库引用**（`@type` 取值，管理器以下拉展示）：

| `@type` | 数据源 | 说明 |
| --- | --- | --- |
| `actor` | `$dataActors` | 角色 |
| `class` | `$dataClasses` | 职业 |
| `skill` | `$dataSkills` | 技能 |
| `item` | `$dataItems` | 物品 |
| `weapon` | `$dataWeapons` | 武器 |
| `armor` | `$dataArmors` | 防具 |
| `enemy` | `$dataEnemies` | 敌人 |
| `troop` | `$dataTroops` | 敌群 |
| `state` | `$dataStates` | 状态 |
| `animation` | `$dataAnimations` | 动画 |
| `common_event` | `$dataCommonEvents` | 公共事件 |
| `switch` | `$dataSystem.switches` | 开关 |
| `variable` | `$dataSystem.variables` | 变量 |

不支持 `tileset`。示例见 `_localmods/TestMod/`、`_localmods/TestDbTypes/`。

**struct / table 示例**：见 `_localmods/TestSchemaMod/TestSchemaMod.js`、`_localmods/mydrop/mydrop.js`。

### 3.2 包结构规范

V4.1 起，**本地**与**工坊**使用同一套包根布局：

**单脚本包**（文件夹名 = 脚本基名）：

```
js/mods/_localmods/老板键模式/
  老板键模式.js
  CHANGELOG.md         # 可选（V4.2 包根）
  preview.png          # 可选
```

**多脚本包**（文件夹名 = 包名，列表每行一个 `.js`）：

```
js/mods/_localmods/多脚本包名/
  modloader.json       # 多脚本必填 version
  CHANGELOG.md         # 可选；整包共用一份
  preview.png          # 可选，包内共用
  Core.js
  FeatA.js
```

**Steam 工坊包**（结构相同，路径在 Steam 库）：

```
<publishedFileId>/
  modloader.json
  preview.png
  YourMod.js
```

| 规则 | 说明 |
| --- | --- |
| 脚本位置 | 包根一层 `*.js`，**不递归**子目录 |
| 无 `modloader.json` | 自动扫描包根全部 `.js`（跳过 `ModLoader.js`） |
| `modloader.json` | `entries` **仅写文件名**，禁止 `/`、`\`、`..` |
| `name` | 包目录名（与 `_localmods/<name>/` 一致）；商店 catalog 展示名同此 |
| `version` | 包版本；**多脚本包必填** |
| `description` | 包简介（Mod 商店 catalog `summary` 来源之一） |
| `CHANGELOG.md` | 可选；**包根唯一文件名**（V4.2）。有版本号时在管理器详情显示「更新日志」；有则进 zip，打包时写入 catalog `changelogUrl`（见商店拓展 plan §5.1） |
| `modId` | 仅 ModResourceLoader：稳定资源别名（工坊包名变化时仍可用） |
| `preview.png` | 固定文件名，包根；详情缩略 + 点击 NW 弹窗大图 |
| 资源文件 | 放在包内子目录（如 `img/`、`docs/`），脚本内路径写相对于游戏根或包内路径 |

**mod_config 键名**：

| 来源 | 键名 | loadPath |
| --- | --- | --- |
| 本地 | `local:<包名>:<脚本基名>` | `../mods/_localmods/<包名>/<脚本基名>` |
| 工坊 | `ws:<fileId>:<脚本基名>` | `../mods/_workshop/<fileId>/<脚本基名>` |


### 3.3 管理器语言包拓展

若你为 **ModLoader 本身** 贡献 UI 翻译（非 Mod 插件内文案），步骤同 [1.4 管理器语言包如何拓展](#14-管理器语言包如何拓展)。Mod 插件的 `@text` 由作者在插件头自行编写，不走 `config/language/`。

### 3.4 制作 Mod 时参考示例

| 示例 | 路径 | 说明 |
| --- | --- | --- |
| `TestMod` | `_localmods/TestMod/TestMod.js` | 基础参数类型、颜色、数据库引用 |
| `TestDbTypes` | `_localmods/TestDbTypes/TestDbTypes.js` | class/troop/animation/switch/variable/common_event |
| `TestSchemaMod` | `_localmods/TestSchemaMod/` | struct、table、嵌套 schema、@text |

**资源路径提示**：V4.1 后 Mod 资源应放在包目录内，例如：

```
js/mods/_localmods/攻略查看器/
  攻略查看器.js
  img/攻略图标.png
  docs/guide/...
```

脚本内加载：`js/mods/_localmods/攻略查看器/img/攻略图标.png`（NW.js 路径相对于游戏根目录）。

### 3.5 通过 Mod 商店发布

面向未开创意工坊、或需额外 HTTPS 分发渠道的作者。完整流程见 **[`tools/modstore/gui/README.md`](../tools/modstore/gui/README.md)**（GUI 打包工具，需 Node.js 18+ 与本机 Git）。

摘要：

1. 在 `_localmods` 按 [3.2 包结构规范](#32-包结构规范) 维护 Mod；多脚本包须在 `modloader.json` 写 `version`；可选包根 `CHANGELOG.md`（有则写入 catalog `changelogUrl`）
2. 双击 `tools/modstore/gui/启动Mod打包工具.bat` → 配置路径与 Gitee/GitHub 仓库
3. **从远程拉取到本地**（首次）→ 扫描 → **打包并生成 catalog** → **推送到远程仓库**
4. 将日志中的 **Catalog URL (https)** 写入整合包 `mod_store.json` 或告知玩家手动订阅

zip 文件名 = `包目录名-<version去V前缀>.zip`（如 `V1.0.0` → `ExampleMod-1.0.0.zip`）。catalog `id` / `packageName` 均等于包目录名。

CLI 等价：`tools/modstore/modStorePublish.js`、`tools/modstore/batchPublishGitee.js`（见 GUI README「与 CLI 的关系」）。
