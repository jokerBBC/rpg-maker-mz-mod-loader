## 1. 理想目录（将来拆文件时）

```
js/mods/
  ModLoader.js              ← 主入口：启动、界面、编排、对外 API（保留）
  modloader/                ← 管理器自用纯逻辑（新建；不是玩家 Mod）
    paramTypeKit.js         ← 类型判定 / 清洗 / 数据库集合归一
    modMetadata.js          ← 插件头解析、schema、note 换行、配置回填
    dependencyResolver.js   ← @base / @orderAfter 解析与五态判定
    paramValues.js          ← 参数值规范化（存档与下发共用）
  config/                   ← 已有：语言包、css、modloader_config
  libs/                     ← 已有：可选扩展（闸门、marked…），不是核心逻辑
  _localmods/ _workshop/    ← 已有：用户/工坊内容
```

命名约定：`modloader/` 下放**可自动测的纯逻辑**；带 DOM、Steam、PluginManager 钩子的留在 `ModLoader.js`。

## 2. 哪些切出去，哪些留主文件

### 建议独立切出（第一～三波）

| 优先级 | 模块 | 大约对应现注释区 | 为什么切 |
|--------|------|------------------|----------|
| 第 1 波 | **类型工具** `paramTypeKit` | 6.1 里非 DOM 部分 | 解析、下发、界面都在用；放在「界面旁」导致归属乱、agent 乱塞 |
| 第 1 波 | **元数据解析** `modMetadata` | 模块 4 | 近期 note/schema/类型改动最热；最适合 fixture 自动测 |
| 第 2 波 | **依赖判定** `dependencyResolver` | 5.4 | 五态规则复杂；表驱动测试收益高 |
| 第 2 波 | **参数值管道** `paramValues` | `buildModFinalParameters` + 与 collect 共用的净化/归一 | 专治「编辑器改了、运行时忘了」 |
| 第 3 波（可选） | **包发现** | 5.1 里 entries 安全规则、脚本发现 | 工坊路径安全；可用假目录测 |
| 第 3 波（可选） | **配置读写核心** | 模块 2 的合并/meta-key 规则 | 注入假 fs 可测；优先级低于上面 |

### 建议保留在 `ModLoader.js`

| 块 | 大约对应 | 为何留主文件 |
|----|----------|--------------|
| 运行时基础 | 模块 1 | 路径常量、日志、挂接 Node |
| 配置 I/O 外壳 | 模块 2 调用处 | 可读真实磁盘；规则核心以后可下沉 |
| 拖放安装 | 模块 3 | 与系统拖放 + 界面强绑 |
| 扫描编排 | 5.1–5.3 编排层 | 调元数据/配置/工坊；本身是「胶水」 |
| 运行时加载钩子 | 5.5 | 依赖 `PluginManager` / 游戏启动 |
| 界面 DOM | 6.2–6.6 | 必须进游戏抽查；agent 难替你测观感 |
| 排序拖拽 UI | 6.3.1 | 只动表现时进游戏玩一下即可；索引小函数可日后微调，不必先拆 |
| 初始化与扩展宿主 | 6.7–6.8 | `window.ModLoader`、libs 扫描、闸门、日志空壳 |

**原则：** 主文件 = **编排 + 界面 + 游戏挂钩**；子文件 = **规则**。

## 3. 每种改动放哪、测什么

| 你想改的事 | 放哪（拆文件后 / 现注释区） | 怎么测才算够 |
|------------|-----------------------------|--------------|
| 新 `@type`（如官方类型、数据库引用） | **类型工具** + 必要时 **元数据**默认值 + **参数值管道**下发；界面只加控件展示 | ① 类型工具/管道自动测 ② `_localmods` 测试 Mod 进游戏点下拉 |
| `@default` / note / `\\n` / schema 默认 | **元数据**（+ 管道若影响下发） | 用假插件头字符串自动测；游戏里打开参数页抽查 |
| struct/table 与顶层控件不一致 | 控件 DOM 可留主文件，但**数值含义**必须走 **参数值管道** | 自动测管道；游戏里各点一种类型 |
| `@base` / `@orderAfter` 文案或状态 | **依赖判定** | 表驱动：缺插件/未开/顺序错等组合；UI 只抽查颜色/提示 |
| 启用 Mod 却缺前置导致崩 | 加载守卫在主文件 5.5，判定规则应与 **依赖判定**一致 | 依赖模块自动测 + 游戏里关前置试一次 |
| 列表筛选 / 详情布局 / 主题 / 语言切换文案 | 主文件界面 + `config/language` | 进游戏看一眼 |
| Steam 风格拖拽排序手感 | 主文件 6.3.1 | 进游戏拖几下（逻辑未改时不必全量回归解析） |
| 冲突日志**内容**（谁覆盖谁） | **不要**进管理器；走 `registerLogEntry`，由前置 Mod 的 `render` | 测前置 Mod；管理器只测「菜单有入口、空壳能打开」 |
| 正版/盗版闸门 | **不要**进管理器核心；`libs/` + `registerManagerGate` | 有/无该文件各测一次能否进管理器 |
| Mod 商店 UI / 下载管线 | **不要**进管理器；`libs/modStore.js` + `registerLogEntry` | 测订阅、下载、角标；管理器只提供 API 与「刷新列表」 |
| Markdown 渲染库 | `libs/marked.min.js`，不要塞回主文件 | 更新日志弹窗打开即可 |
| 工坊 `entries` 路径穿越、只允许文件名 | 将来 **包发现**；现 5.1 | 假 manifest 自动测；游戏里装一个合法包抽查 |
| `mod_config` 键、meta 键过滤 | 配置核心 / 模块 2 | 假配置对象自动测；保存后看 json |
| 对外 API（`registerLogEntry` 等） | 主文件 6.8，保持稳定 | 前置 Mod 注册后看设置菜单 |

## 4. 什么不该进管理器

已经做过、以后也要守住的边界：

1. **冲突详情 UI / 数据冲突算法** → 前置 Mod（空壳 + `registerLogEntry`）  
2. **盗版检测** → `libs` 闸门，文件在即开、删即关  
3. **Mod 商店**（订阅、下载、解压、商店面板）→ `libs/modStore.js`，文件在即开、删即关  
4. **具体游戏玩法、某功能 Mod 的业务** → `_localmods` / 工坊包，不要写进 `ModLoader.js`  
5. **大段第三方库** → `libs/`，管理器只加载  
6. **整份 CSS、语言包** → 已外置 `config/`，不要再内嵌回主文件养双份  

拿不准时问一句：**「这是所有 Mod 都需要的管理能力，还是某个前置/功能自己的事？」** 后者不要进主文件。

## 6. 给 agent / 以后的自己的短规则

1. 先查本表「放哪」，再改代码；没有合适格子 → 先问是否不该进管理器。  
2. 纯逻辑改动：优先补/跑自动测试，再进游戏抽查 UI。  
3. 只改观感/拖拽/文案：进游戏抽查即可，不必假装测了全套解析。  
4. 新增 `@type`：类型工具 + 管道一起改，并加/改测试 Mod；不要只在某个 `render*` 里写死。  
5. 单文件阶段也按上表注释区放；**禁止**为了图省事把规则函数塞进随机 UI 函数下面。
